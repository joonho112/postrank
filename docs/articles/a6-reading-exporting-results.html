Reading and exporting grading results

Source: vignettes/a6-reading-exporting-results.Rmd
a6-reading-exporting-results.Rmd

A postrank() result stores the assigned integer grades, the ordered and unordered pair counts, the posterior expected loss, and the solver’s status, lower bound, and gap. When you export a table or report, keep those policy settings and solver records alongside the grades so a reader knows what loss was minimized and whether the solver finished within tolerance.

Below we load the two stored tutorial results introduced in Getting started: grading with one or two criteria using postrank_example(). Reading stored results runs no solver and fits no model; the same accessors and export functions work on any postrank_analysis returned by postrank().

library(postrank)
sites <- pr_tutorial
one <- postrank_example("tutorial_one")
two <- postrank_example("tutorial_two")

Printing one shows the entity and grade counts (6 entities in 3 grades), the posterior loss (0.0417), the ordered (“disclosed”, 12) and unordered (“withheld”, 3) pair counts, the solver status and gap, and any warnings. Grade 1 is the highest priority, and sharing a grade leaves that pair unordered without claiming that the two sites have equal scores; see Getting started: grading with one or two criteria.

summary(one) adds the policy settings (weights, G_max, and tau), a per-criterion table, the availability of optional summaries, and the full text of recorded warnings. Under Optional results:, "unsupported for this input" (here for Monte Carlo fragility, which was requested by default yet requires posterior draws rather than an analytic normal distribution) is distinct from "not requested" (meaning FALSE was passed before checking input support: crossfit = TRUE also requires joint draws, whereas diagnostics = TRUE on a normal input evaluates conditional-normal summaries under the "Monte Carlo diagnostics" label). Neither label means a value of zero, and summary() never runs new calculations.

On joint IID or MCMC draw inputs, postrank() computes pairwise Monte Carlo fragility by default while leaving cross-fitting and full trace diagnostics off unless requested. We can inspect extras and fragility$summary on the stored 30-site, three-criterion draw analysis (analysis_30x3_tau35):

a35 <- postrank_example("analysis_30x3_tau35")

  data.frame(requested = e[["requested"]], available = e[["available"]],
    reason = if (is.null(e[["reason"]])) "" else e[["reason"]])

A pair is flagged as fragile when its estimated weighted error in the likelier direction is within z = 2 Monte Carlo standard errors of tau; these pairwise flags are descriptive summaries of simulation noise and need not change the jointly chosen grades (when diagnostics = TRUE or crossfit = TRUE, inspect x$diagnostics and x$crossfit; see Monte Carlo diagnostics, cross-fitting, and IID bounds).

To add input and problem identity hashes, package and solver versions, and source descriptions to the console summary, set details = TRUE. To capture the formatted console lines as a character vector (matching the exported format_postrank_*_cli() wrappers), call format():

detailed <- summary(one, details = TRUE)
head(format(one, width = 72, tier = 2), 4)
#> [1] "<postrank_analysis>  6 entities in 3 grades (sizes 2 / 2 / 2)"
#> [2] "  One criterion: score_A."                                    
#> [3] "  Posterior loss: 0.0417."                                    
#> [4] "  Disclosed 12 of 15 pairs (80.0%); withheld 3."

Printing detailed displays those extra provenance lines (including the note "Bounds are solver values; the gap is not regret", where regret means excess loss relative to the best grading under the true posterior), and cat(..., sep = "\n") writes captured format() lines to a log or file. In scripts, extract numbers with the accessors below rather than parsing printed console text.

Grade tables and report-card tables 

grade_table <- as.data.frame(one)
grade_table
#>   entity_id grade
#> 1         A     1
#> 2         B     1
#> 3         C     2
#> 4         D     2
#> 5         E     3
#> 6         F     3

By default, as.data.frame() returns a two-column data frame with character entity_id and integer grade in the original input entity order. Calling as.data.frame() on a postrank_analysis, its postrank_fit, or a postrank_baseline always returns these same two columns, whether or not a report card was prepared:

identical(grade_table$entity_id, sites$one$entity_ids)
#> [1] TRUE
identical(grade_table, as.data.frame(one$fit))
#> [1] TRUE

Join results back to your own entity metadata by entity_id rather than by row position or formatted display labels.

To extract the marginal posterior summaries alongside the grades, request what = "report_card":

card <- as.data.frame(one, what = "report_card")

Along with entity_id and grade, card includes sort_rank, pair counts for each entity (n_above, n_below, and n_withheld), and per-criterion columns mean_<criterion>, lower_<criterion>, upper_<criterion>, and expected_rank_<criterion> (here 90% equal-tail marginal score intervals). If a criterion was negated at input construction (orientation = "lower"), these columns remain on that negated scale, so negating back to raw units swaps lower_<criterion> and upper_<criterion>. Select columns by name rather than column index. When a marginal posterior is skewed, its posterior mean can sit outside its equal-tail interval, and report-card tables and plots show the stored values unchanged; likewise, inputs that carry precomputed intervals only at one level (such as 90% in pr_case_cde and pr_case_krw, or 95% in pr_case_alabama) cannot recompute other interval levels.

Rows of as.data.frame(x, what = "report_card") are ordered by grade and then by the report card’s secondary sort rule (sort_rank), which can differ from the original input order:

list(
  input_order = as.data.frame(two)$entity_id,
  report_card_order = as.data.frame(two, what = "report_card")$entity_id
)
#> $input_order
#> [1] "A" "B" "C" "D" "E" "F"
#> 
#> $report_card_order
#> [1] "A" "C" "B" "D" "E" "F"

If a report card could not be built (for example, when an input supplies pairwise comparison probabilities without marginal intervals), calling as.data.frame(x, what = "report_card") stops with an error explaining why it is unavailable, while as.data.frame(x) still returns the two-column grade table.

Extracting grades, pair relations, profiles, and loss 

grades <- get_grades(one)
grades
#> A B C D E F 
#> 1 1 2 2 3 3
relations <- get_relations(one)
relations[c("A", "B", "C"), c("A", "B", "C")]
#>         entity_j
#> entity_i  A  B C
#>        A  0  0 1
#>        B  0  0 1
#>        C -1 -1 0

get_grades() returns an integer vector named by entity_id. get_relations() returns an n x n integer matrix in which entry [i, j] is 1 when row entity i is placed in a higher-priority grade than column entity j, -1 for the opposite order, and 0 when the pair shares a grade (or on the diagonal). Thus [ "A", "B" ] is 0 (left unordered) and [ "A", "C" ] is 1 (A ordered above C).

profile <- get_profile(one)
knitr::kable(profile[, c("criterion", "weight", "E", "E_over_M",
  "E_over_N", "risk")], digits = 5, row.names = FALSE)
criterion weight E E_over_M E_over_N risk
score_A 1 0.02477 0.00165 0.00206 0.04165 
risk <- get_risk(one)
risk
#> $risk
#> [1] 0.04165164
#> 
#> $lower_bound
#> [1] 0.04165164
#> 
#> $gap
#> [1] 0
#> 
#> $status
#> [1] "optimal"

In get_profile(), E is the posterior expected number of wrong-direction ordered pairs on that criterion, E_over_N divides E by the number of ordered pairs N, E_over_M divides E by all M pairs, and risk adds the unordered-pair cost tau * (M - N) / M:

N <- sum(relations[upper.tri(relations)] != 0L)
M <- choose(length(grades), 2)
tau <- 0.2
c(from_parts = (profile$E + tau * (M - N)) / M, stored = risk$risk)
#> from_parts     stored 
#> 0.04165164 0.04165164

With multiple criteria, get_profile(two) has one row per criterion, while get_risk(two) returns a named list (risk, lower_bound, gap, and status) for the overall objective (weighted average of criterion losses by default, or worst-criterion loss when objective = "minimax").

You can also evaluate any fixed integer grade vector on the same input without running a solver via postrank_evaluate(). Placing every site in grade 1 leaves all pairs unordered:

withheld <- postrank_evaluate(
  setNames(rep(1L, length(grades)), names(grades)), sites$one,
  weights = c(score_A = 1), tau = 0.2
)
withheld[c("N", "E_over_N", "primary_risk")]
#> $N
#> [1] 0
#> 
#> $E_over_N
#> score_A 
#>      NA 
#> 
#> $primary_risk
#> [1] 0.2

Because N is 0, E_over_N is NA (not 0) and primary_risk equals tau (0.2). That all-unordered report is a valid one-grade action, which is distinct from a failed or timed-out solver run that returned no checked grading.

Solver status, bounds, and missing-grade states

Both stored tutorial results have status "optimal". On larger problems or tight time limits, a solver run can stop before proving optimality or before finding any checked grading. Always read the status alongside whether a checked grading is present (!is.null(get_grades(x))):

Solver status and grading state How to read it
"optimal", with a checked grading Optimal within the requested solver tolerances; check lower_bound, gap, and warnings for the numerical details.
"feasible_not_certified", with a checked grading A valid grading was found and checked, while the lower bound or gap did not reach the requested optimality tolerance.
"time_limit", with a checked grading Search stopped at the time limit; the stored best grading can be used and reported together with its remaining gap (or NA if no bound was obtained).
"time_limit", without a checked grading Search stopped before any candidate grading passed validation; there are no grades to use, though status and any lower_bound remain recorded.
"infeasible" The requested constraints (for example, tight criterion error budgets q or exact_G) cannot be satisfied simultaneously; this is not an all-unordered grading.

Statuses "numerical_error", "unknown", or "unbounded" indicate solver trouble; inspect the recorded warnings before using any output. As explained in Computing grades, choosing settings, and reading solver bounds, the optimization gap measures how close the returned grading’s loss is to the solver’s lower bound for the supplied comparison probabilities, not posterior uncertainty in the entity scores.

When a run finishes without a checked grading, get_grades() and get_relations() return NULL, as.data.frame() and get_profile() return zero-row data frames with their normal column names and types, and get_risk() keeps status and any lower_bound while setting risk and gap to NA. Never substitute rep(1L, n) for NULL grades: NULL means no checked grading was returned.

Saving CSV tables and RDS objects

Use CSV when exporting flat tables to other software, and RDS when saving the complete postrank_analysis object in R with its settings, report card, solver bounds, and warnings intact. Here we write both to a fresh temporary folder:

export_dir <- tempfile("postrank-exports-")
dir.create(export_dir)
csv_file <- file.path(export_dir, "grades.csv")
rds_file <- file.path(export_dir, "analysis.rds")
write.csv(grade_table, csv_file, row.names = FALSE)
csv_again <- read.csv(csv_file,
  colClasses = c(entity_id = "character", grade = "integer"))
identical(csv_again, grade_table)
#> [1] TRUE

Specify colClasses = c(entity_id = "character", grade = "integer") when reading CSV files back into R so leading zeros in IDs such as "01001" are preserved, and row.names = FALSE when writing so no extra row-number column is added. Because a CSV table drops policy settings, interval levels, and solver status, record those alongside any exported table.

saveRDS(one, rds_file)
restored <- readRDS(rds_file)
identical(get_grades(restored), grades)
#> [1] TRUE
identical(get_risk(restored), risk)
#> [1] TRUE
identical(as.data.frame(restored, what = "report_card"), card)
#> [1] TRUE

readRDS() restores the full analysis object without calling a solver. Keep the postrank version and source input alongside archived .rds files for long-term reproducibility.

Writing a standalone HTML report

postrank_report() writes a self-contained English HTML report from stored results without running a solver. Note that its first argument must be the postrank_fit object (one$fit, not one directly), while passing analysis = one supplies the report card and any stored optional summaries (matching diagnostics stored on analysis or passed via diagnostics =, including postrank_coefficient_diagnose() summaries and their NA_reason fields, are included when present; missing summaries stay marked unavailable and are never recomputed):

html_file <- file.path(export_dir, "grades-report.html")
report <- postrank_report(one$fit, analysis = one,
  output_file = html_file, lang = "en")
report
#> <postrank_report>  Report saved as grades-report.html
#>   11 sections; 2 available figures.
#>   6 entities in 3 grades; disclosed 80.0% of pairs.
#>   Optimal within solver tolerances.
#>   !  1 warning recorded: Reported lower bound exceeded the validated action ris...
#>   i  Use output_file in postrank_report() to save the English HTML report.
basename(report$output_file)
#> [1] "grades-report.html"

Line 1 of print(report) (Report saved as grades-report.html) confirms that the file was written to output_file (the generic footer line mentioning output_file is always printed by postrank_report’s console formatter). Figures are embedded directly in the HTML file for offline viewing; set figures = FALSE for a smaller text-and-table report. postrank_report() refuses to overwrite an existing output_file, so choose a new file path for each saved report version, and write to a project directory rather than tempfile() when keeping reports across R sessions.
