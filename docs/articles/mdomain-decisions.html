Separate domain rules versus joint multidomain protection

Source: vignettes/mdomain-decisions.Rmd
mdomain-decisions.Rmd

A multidomain report card assigns each unit one integer grade in each domain: Grade 1 is the highest priority within that domain, and giving two units the same grade leaves that pair unordered without claiming that their targets are equal. This article explains when each domain’s grade column can be chosen on its own and when a joint cross-domain protection rule changes the chosen profile. All executable examples use small synthetic distributions, run offline without an external MIP or LP solver, and evaluate exact fractions when the suggested gmp package (install.packages("gmp")) is installed.

library(postrank)

Additive domain loss and separate column choices

Let GdG_d be the integer grade column in domain dd, FdF_d the number of wrong-direction ordered pairs in a posterior state (counting any strict ordering of equal targets as wrong), and TdT_d the number of unordered (withheld) pairs among all M=(n2)M = \binom{n}{2} original unit pairs. With nonnegative domain weights wdw_d and unordered-pair costs τd\tau_d, the additive posterior expected loss is

R(G)=∑dwd𝔼[Fd]+τdTdM. R(G) = \sum_d w_d \frac{\mathbb{E}[F_d] + \tau_d T_d}{M}.

Each domain’s loss term depends only on within-domain pairwise probabilities. Whenever the declared candidate set is a Cartesian product of per-domain column sets and every constraint is within-domain (such as equality_classes, grade caps, or per-domain expected-error budgets q), the feasible set is also a Cartesian product: minimizing each weighted domain term on its own minimizes R(G)R(G) regardless of how domains depend on one another in the posterior (for a zero-weight domain, every feasible column achieves zero weighted contribution).

Adding a joint exceedance cap across domains couples the feasible set. Writing NdN_d for the number of ordered pairs in domain dd’s protection scope, a joint cap requires

J(G)=Pr⁡(at least one d has Fd>tdNd)≤α. J(G) = \Pr(\text{at least one } d \text{ has } F_d > t_d N_d) \le \alpha.

Because this union event is evaluated inside each joint posterior state, changing how errors co-occur across domains can change J(G)J(G) while leaving every marginal domain error probability and R(G)R(G) unchanged (when Nd=0N_d = 0, Fd>tdNdF_d > t_d N_d cannot occur in domain dd, and that domain’s error proportion is NA rather than a measured zero).

Two units, two domains, and identical marginal errors

Consider two units (A and B) across two domains (one and two). In a normal state, A is above B (2 > 1); in a reversed state, B is above A (1 < 2). The two discrete distributions below have identical marginal reversal probability 1/10 in each domain, differing only in whether reversals happen together or in separate states:

Distribution Normal in both Reverse domain one only Reverse domain two only Reverse both
coincident 9/10 0 0 1/10
disjoint 8/10 1/10 1/10 0

We set equal domain weights (1/2 each by default), unordered-pair cost tau = "1/4", strict error-proportion threshold t = "0", and joint exceedance cap alpha = "3/20" using character strings so exact rational values are kept:

units <- c("A", "B")
domains <- c("one", "two")
targets <- setNames(lapply(domains, function(d) list(
  definition = paste("Fictional priority in domain", d),
  units = "arbitrary priority units", orientation = "larger_is_higher",
  equality_classes = units,
  equality_provenance = "A and B are distinct modeled targets."
)), domains)

make_states <- function(reverse, ids) {
  x <- array(0, c(nrow(reverse), 2L, 2L), dimnames = list(ids, units, domains))
  for (d in seq_along(domains)) {
    x[, "A", d] <- ifelse(reverse[, d], 1, 2)
    x[, "B", d] <- ifelse(reverse[, d], 2, 1)
  }
  x
}
make_law <- function(id, reverse, masses) {
  postrank_mdomain_input(
    make_states(reverse, paste0(id, "-", seq_len(nrow(reverse)))),
    targets = targets,
    provenance = list(
      input_id = id, law_id = id, proper_law = TRUE,
      joint_generation = "Complete finite support authored in this article.",
      sampling_assumptions = list(
        finite_support_origin = "All support states and exact masses listed here.")
    ),
    representation = "exact_finite_law", masses = masses)
}
laws <- list(
  coincident = make_law("coincident",
    rbind(c(FALSE, FALSE), c(TRUE, TRUE)), c("9/10", "1/10")),
  disjoint = make_law("disjoint",
    rbind(c(FALSE, FALSE), c(TRUE, FALSE), c(FALSE, TRUE)),
    c("8/10", "1/10", "1/10"))
)
policy <- postrank_mdomain_decision(tau = "1/4", t = "0", alpha = "3/20")

With two units, each domain has three possible grade columns: withhold (1, 1), A_above_B (1, 2), and B_above_A (2, 1). Their Cartesian product contains all nine two-domain cards (max_actions = 9L). Optimality in postrank_mdomain_solve() holds within the declared candidate set (which here exhausts all two-unit profiles):

columns <- list(withhold = c(A = 1L, B = 1L),
  A_above_B = c(A = 1L, B = 2L), B_above_A = c(A = 2L, B = 1L))
families <- lapply(laws, postrank_mdomain_family,
  columns = list(one = columns, two = columns), max_actions = 9L)
fits <- setNames(lapply(names(laws), function(id) {
  postrank_mdomain_solve(laws[[id]], families[[id]], policy, max_actions = 9L)
}), names(laws))
column_label <- function(g) {
  if (g[1L] == g[2L]) "withhold" else if (g[1L] < g[2L]) "A above B" else "B above A"
}
candidate_display <- function(fit) {
  tab <- fit[["candidate_table"]]
  actions <- fit[["solution"]][["actions"]][tab[["action_id"]]]
  data.frame(
    one = vapply(actions, function(g) column_label(g[, "one"]), ""),
    two = vapply(actions, function(g) column_label(g[, "two"]), ""),
    risk = tab[["risk_exact"]], joint_probability = tab[["J_exact"]],
    feasible = tab[["feasible_for_represented_measure"]],
    optimal = tab[["optimal"]], row.names = NULL
  )
}

Removing the joint exceedance cap (t = NULL) restores separate domain optimization, making (A above B, A above B) optimal (risk = 1/10) under both laws—confirming that the union constraint is what coupled the domains, and that pairing separate marginal simulations arbitrarily cannot determine which joint distribution applies:

separable_policy <- postrank_mdomain_decision(tau = "1/4", t = NULL)
separate_fits <- setNames(lapply(names(laws), function(id) {
  postrank_mdomain_solve(laws[[id]], families[[id]], separable_policy, max_actions = 9L)
}), names(laws))

Reading the stored 40-site synthetic illustration

The JSON file extdata/mdomain/synthetic40-card.json stores summary tables and grade matrices for 40 synthetic sites adapted from JoonHo Lee’s Need-Based Prekindergarten Funding tutorial. Domain S measures student-composition economic need and domain C measures catchment-community economic need (larger values mean higher priority in both domains, with M = 780 unordered site pairs). Two site pairs (S05/S06 and S21/S22) share community C equality classes while all 40 student S targets remain distinct (including conditional predictive S targets for new sites).

In the external tutorial workflow, candidate selection used 8,000 post-warmup states from chains 1–2 across a declared 7 x 7 = 49 candidate set (with candidate columns ordered on those selection states), followed by fixed-card evaluation on 8,000 states from chains 3–4. Both cases use equal domain weights, tau = "1/10", q = "1/20", and alpha = "1/20", while t shifts from 5% (primary) to 10% (wide).

This article reads the stored grades and summary counts directly; it does not rerun the 40-site selection, load the external posterior archive, or run a new validation. Full workflow details are in the tutorial’s reproducibility appendix (the source commit, relative path, SHA-256 hash, and adaptations are recorded in the JSON file):

Inspecting MCMC exceedance-event histories for a fixed multidomain card

To inspect how a Markov chain explores the exceedance event of a fixed report card, pass representation = "mcmc_equal_weight_draws" with state_origin and call postrank_mdomain_assess(..., method = "mcmc"). Below we simulate two short unequal-length two-state Markov chains (24 and 31 iterations, transition probabilities 1/10 for 0 -> 1 and 2/5 for 1 -> 0, stationary reversal probability 1/5; illustrative lengths only, independent of the 40-site file above):

simulate_chain <- function(n) {
  z <- logical(n)
  z[1L] <- stats::runif(1) < 1 / 5
  for (i in 2:n) {
    z[i] <- if (z[i - 1L]) stats::runif(1) >= 2 / 5 else stats::runif(1) < 1 / 10
  }
  z
}
set.seed(1202)
chains <- list(chain_A = simulate_chain(24L), chain_B = simulate_chain(31L))
z <- unlist(chains, use.names = FALSE)
history <- data.frame(
  source_index = seq_along(z),
  chain_id = rep(names(chains), lengths(chains)),
  iteration_id = unlist(lapply(chains, seq_along), use.names = FALSE)
)

Next we wrap the two-chain history in postrank_mdomain_input() and evaluate postrank_mdomain_assess(..., method = "mcmc", batch_size = 10L) on the fixed dual card (A above B, A above B):

history_input <- postrank_mdomain_input(

    joint_generation = "Both domains share the simulated binary chain state.",

    sampling_assumptions = list(
      sampler = "Two-state Markov transition simulator.",

Per-chain hit counts, max_zero_run, and batch-level tables (assessment$native$batch_table, which keeps trailing partial batches rather than dropping them) summarize how often the chain visited the exceedance event (when combining chains of unequal length, weight by n_retained rather than averaging unweighted chain rates). MCMC diagnostics are descriptive summaries, not guarantees: they do not provide an IID binomial certificate, prove convergence, or turn split chains into independent validation samples. See ?postrank_mdomain_assess for the fixed-sample method = "iid" design fields and Grading entities across multiple domains for the step-by-step multidomain workflow.
