Strict inputs, declarations and external producers

Source: vignettes/inputs-and-producers.Rmd
inputs-and-producers.Rmd

This retained reference preserves the original examples and article URL. Analysis of supplied posterior results describes input construction, and Posterior inputs and pairwise probabilities examines the information available under each representation.

postrank accepts posterior draws or coefficients from an external estimation procedure, together with declarations of their scientific meaning and sampling history. We describe the input routes, eight required declarations, JSON representation, Gaussian and mixture constructors, fixed-grade evaluation and transfer from an external estimation pipeline. The package does not fit the underlying models. Solver results in this article are read from source-bound caches, with no new optimization.

library(postrank)
source(system.file("scripts", "_vignette-setup.R", package = "postrank", mustWork = TRUE), local = TRUE)
has_posterior <- requireNamespace("posterior", quietly = TRUE)   # optional producer route below

(a) An array of draws with eight declarations

The array interface accepts a numeric S x n x K array indexed by draw, entity and criterion, an explicit sampling regime, and a postrank_declarations() bundle. All eight declarations are required and have no defaults; generic placeholders such as "unknown" or "TBD" are rejected. The declarations below describe the illustrative analysis and must be replaced by the corresponding statements for an application.

decl <- postrank_declarations(
  targets = data.frame(criterion_id = c("need1", "need2"),
    estimand = "Latent need of each site (illustration)", entity_population = "Six example sites",
    time_reference = "Example year", units = "standardized units"),
  context = list(cohort_id = "example-cohort", data_version = "1",
    data_conditioning = "Simulated values for this article",
    model_summary = "Independent standard Normal draws (no data)"),
  provenance = list(producer = "inputs-and-producers vignette", artifact_id = "example-array",
    construction_note = "Generated in this article with set.seed(20261024)"),
  origin = list(source_id = "vignette", fit_id = "none", model_id = "standard-normal",
    source_format = "R array", source_artifact = "inputs-and-producers.Rmd"),
  identification_note = "The targets are the simulated coordinates themselves.",
  tie_justification = "Continuous draws; exact ties between distinct sites have probability zero.",
  joint_generation = "Each draw holds all sites and criteria from one simulated state.",
  sampling_provenance = "IID draws from the stated Normal law; nothing discarded or thinned.")
names(decl)

For numeric arrays, postrank_draws() calls the strict constructor postrank_draws_from_array(), which accepts the eight declarations as separate arguments and returns a validated postrank_draws object. MCMC input additionally requires a declared chain layout (chains, warmup_per_chain and thin, with thin = 1L for unthinned output) and values stored chain by chain. For a criterion with higher priority assigned to smaller values, orientation = c(need2 = "lower") negates the values once and records the transformation in the target’s source_transform.

An incomplete declaration bundle produces an error:

e <- tryCatch(postrank_declarations(targets = decl$targets, context = decl$context),
  error = identity)
conditionMessage(e)
#> [1] "$.declarations: missing required scientific declarations: provenance, origin, identification_note, tie_justification, joint_generation, sampling_provenance (they are not inferred or filled with placeholders)"

Declaration checks by input route

All routes require the declarations in their input schema. The high-level array constructor also rejects generic placeholder tokens in descriptive text. This text check does not establish the scientific validity of the declarations.

Input route Declaration checks in 0.9.x
postrank_declarations() and the high-level array constructor Required bundle fields and placeholder-token checks, followed by structural validation
Direct postrank_draws_from_array() Legacy required declarations and structural validation
Existing postrank_draws, canonical JSON read/write Legacy declaration-presence and structural checks; no added token lint
Criterionwise matrix metadata and posterior metadata bridge Canonical metadata/coordinate checks; no added token lint

The bundle checks the four narrative statements and required descriptive fields in targets, context, provenance and origin. Criterion IDs follow the ID rules; fit_id and data_version permit labels such as "none" and are not subject to the placeholder-token check. Passing a canonical route does not imply that the declaration bundle’s placeholder-token check was run. No route verifies jointness, identification or convergence as scientific facts.

The regenerated values are compared with the stored sample at absolute tolerance 1e-12; dimensions and labels must agree exactly. This allows floating-point variation across platforms without replacing the frozen input or its identity. Sourcing defines the function without drawing values or writing files; the function also preserves the caller RNG state. IDs are character labels. Missing or nonfinite targets, unresolved identification, observed entity ties and contradictory histories are rejected, without jitter or hidden reordering.

copy_path <- tempfile(fileext = ".json")
write_postrank_draws(draws, copy_path)
roundtrip <- read_postrank_draws(copy_path)
stopifnot(identical(roundtrip$joint_draws$tensor$values,
                    draws$joint_draws$tensor$values))
unlink(copy_path)

The strict JSON reader rejects decoded duplicate keys, malformed numbers, unsafe integer metadata and invalid Unicode surrogates. Coordinates and singleton axes are preserved. These checks do not constitute general schema validation.

(c) Criterionwise matrices and posterior draws

When each criterion comes from its own fit, there is no joint cross-criterion state. A named list of S_k x n matrices (one per criterion; the S_k may differ) enters with complete canonical criterionwise metadata: one declared block per criterion with its own origin, sampling record, draw index and variable map. The matrix values are inserted into those blocks; no joint state is inferred.

# `metadata` is a canonical applied-0.1 payload with dependence_mode =
# "criterionwise_expected_only" and one criterion_blocks[[k]] per criterion,
# each without its matrix values (see ?postrank_draws and ?as_postrank_draws).
draws_cw <- postrank_draws(list(need1 = m1, need2 = m2), metadata = metadata)

A posterior draws_array, draws_df or draws_matrix enters with canonical joint metadata, explicit variable-mapping records and the source coordinate of every retained draw. Here a producer has written the toy’s states as a one-chain draws_array with variables theta[i,k]; postrank maps them back and obtains the identical object.

if (has_posterior) {
  meta <- make_postrank_synthetic_input()
  vals <- meta$joint_draws$tensor$values
  map <- meta$joint_draws$variable_map
  vars <- vapply(map, `[[`, "", "source_target_variable_id")
  src <- array(NA_real_, c(dim(vals)[1], 1L, length(vars)),
    dimnames = list(iteration = NULL, chain = "1", variable = vars))
  for (m in seq_along(map)) src[, 1, vars[m]] <- vals[, map[[m]]$entity_id, map[[m]]$criterion_id]
  coords <- lapply(seq_len(dim(vals)[1]), function(s)
    list(slot_id = dimnames(vals)$draw[[s]], iteration_index = s, chain_index = 1L))
  meta$joint_draws$tensor$values <- NULL          # the values come from the producer
  from_posterior <- postrank_draws(posterior::as_draws_array(src), variables = map,
    metadata = meta, source_coordinates = coords)
  identical(from_posterior$validation$input_identity, postrank_toy$validation$input_identity)
}
#> [1] TRUE

(d) Gaussian and mixture coefficients

Posterior information may be supplied as coefficients rather than draws. The Gaussian constructor calculates pairwise error probabilities from posterior means and covariances under an explicit conditional-independence declaration, with six required provenance fields. The object pr_example_gaussian represents the fixed law underlying pr_example_draws in this form.

The report card uses analytic Gaussian intervals, with interval_source equal to gaussian_analytic. Thus posterior means and intervals remain available for typed coefficient input, whereas unsupported quantities remain unavailable. Mixture intervals are obtained by numerical inversion of the marginal CDF. If an endpoint fails the probability tolerance in the target’s units, the result records posterior_quantile_failure. A valid fit is retained when this prevents construction of the report-card extra, and the reason for the unavailable extra is recorded.

Prepared coefficient diagnostics can also be included in a report without recomputing them:

An analytic Gaussian law has no hyperstate Monte Carlo trace, so its MCSE is unavailable, not zero. For a shared-hyperstate mixture, conditional-risk metrics describe integration of expected weighted risk over hyperstates; they do not describe target-loss draws or their dispersion. Eligible hyperparameter-MCMC metrics need original chain_history supplied to postrank_coefficient_diagnose(); the convenience postrank_diagnose() dispatch supplies no such history. Finite metrics and the report do not establish convergence, post-selection coverage or regret guarantees.

The coefficient estimates from 4,000 IID draws can be compared with the known-law probabilities. Each e[i,j,k] has Monte Carlo standard error bounded by sqrt(.25 / 4000); the fixture’s regression band is five times this value.

pw <- postrank_pairwise(pr_example_draws)
delta <- pw$e - pr_example_gaussian$e
c(max_pointwise_error = max(abs(delta), na.rm = TRUE), band = 5 * sqrt(.25 / 4000))
#> max_pointwise_error                band 
#>          0.02850931          0.03952847

A pointwise coefficient error differs from a weighted coefficient envelope, which bounds fixed-action risk error uniformly for a specified weight vector. The two quantities are not interchangeable.

Arbitrary coefficient arrays are not accepted by these typed-law constructors. The current postrank_probabilities() interface separately accepts validated tie-free comparison probabilities, as described in the posterior-input article.

(e) Directional errors and a fixed action

This user-supplied action places 001 above the others and withholds their mutual comparison. It is not optimized. With M available unordered pairs and N disclosed directions, risk is (sum(weights*E)+tau*(M-N))/M. E_over_M and E_over_N have different denominators. Criterion-named weights are explicit loss preferences and are not automatically normalized.

(f) A producer pipeline outside the package

The methods book’s hierarchical model is a normal-inverse-Wishart example: site-level latent needs with a normal measurement model and an inverse-Wishart prior on their covariance, fitted by MCMC. Estimation is conducted outside postrank. The following unevaluated code illustrates the transfer of latent draws from four chains of 1,000 retained iterations each, after 1,000 warmup iterations and without thinning:

# theta: 4000 x n x K array of retained draws, stored chain by chain
# (rows 1-1000 chain 1, 1001-2000 chain 2, ...), produced by your own Stan/JAGS run.
decl <- postrank_declarations(
  targets = my_targets, context = my_context, provenance = my_provenance, origin = my_origin,
  identification_note = "...", tie_justification = "...",
  joint_generation = "Each retained iteration holds all sites and criteria from one MCMC state.",
  sampling_provenance = "4 NUTS chains, 1000 warmup + 1000 retained iterations each, no thinning.")
hb_draws <- postrank_draws(theta, regime = "mcmc", chains = 4L, warmup_per_chain = 1000L,
  thin = 1L, declarations = decl)

The repository’s Stan workflow provides an external posterior-production pipeline. The following unevaluated code requires labeled inputs and scientific metadata conforming to that pipeline’s contract.

for (file in sort(list.files("producers/R", pattern = "[.]R$", full.names = TRUE)))
  source(file)

Structural export does not prove sampler adequacy or model validity. Unknown imports, variational and optimization output are not accepted as MCMC draws.

These are descriptive IID standard errors for the toy, not certificates. For MCMC, the optional posterior package supplies Rhat, bulk and tail ESS and MCSE; ESS is not an IID sample size.

The conditional IID reference calculation applies only when sample sizes and alpha were fixed before sampling; for the toy they were fixed in its generator.
