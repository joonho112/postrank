postrank: Posterior Ranking with Integer Grades

postrank-package.Rd

Posterior information on one or several criteria is used to assign an integer grade to each entity under a declared loss. For several criteria, the original P1 entry points assign one common grade. Multidomain P2 entry points retain a separate grade for each domain. The input is an existing posterior representation, supplied as draws, supported analytic laws or previously calculated comparison probabilities, together with scientific declarations and numerical qualifications. The package does not fit a statistical model.

Interpretation of grades

Grade 1 is the highest-priority block; larger targets mean higher priority, and only the order and equality of grade labels matter. A shared grade withholds the comparison of its members and asserts no equality of the entities. The procedure seeks a grade minimizing the declared weighted wrong-direction loss plus the withholding cost tau, and reports the validated incumbent with the solver's bound and gap; withholding every comparison, with risk tau, is a legitimate action.

Getting started

pr_tutorial provides the same six fictional sites with one or two criteria in vignette("a1-getting-started", package = "postrank"). The Applied guides present empirical cases and the Methods guides describe the loss, information requirements, optimization and numerical uncertainty. Stored-result views need no optimizer. A fresh solve uses an explicitly selected backend, the postrank.backend option, or Gurobi in that order. HiGHS is an explicit alternative; there is no silent backend fallback.

Multidomain profiles

postrank_mdomain_input retains identified unit-by-domain states and declared target laws. A named grade matrix reports a separate order in each domain; a shared domain grade withholds direction. postrank_mdomain_decision specifies additive losses and mean or direct joint-event guards. postrank_mdomain_evaluate evaluates a fixed matrix; postrank_mdomain_family and postrank_mdomain_solve select within a complete declared candidate bank. This bank is the stated scope of optimality. postrank_mdomain_grades extracts verified grades, postrank_mdomain_assess distinguishes finite-law, conditional iid and descriptive MCMC routes, and postrank_plot_mdomain displays three stored-card views. Profile computation uses optional gmp arithmetic and requires no MIP backend. Scientific sampling and proper-law declarations are retained, not independently established. See vignette("mdomain-quickstart", package = "postrank") and vignette("mdomain-decisions", package = "postrank").

Genuine target ties

The separate postrank_tie_capabilities() domain makes equality neutral in both wrong-direction and withheld-comparison loss. It supports guarded weighted at-most-G label-MIP problems through distinct postrank_tie_* entry points. Its all-withhold risk is R0, which can be below tau. Ordinary constructors retain their tie-free interpretation.

Case-study data

The three case-study inputs are adapted from public sources and retain source-specific conditions, separate from the package code license. The CDE input preserves source attribution, KRW retains its source CC-BY-NC notice with the license version unspecified, and Alabama retains CC BY 4.0 attribution. Details are given in the data help pages and the installed DATA-NOTICE.

Citation

citation("postrank") returns the package, its theory book and the report-card method of Kline, Rose and Walters (2024), in that order. The book is Decisions from noisy multidimensional indicators: Theory, evidence, and posterior grading (Version 1.0.0), doi:10.5281/zenodo.23790260 . The method reference is A discrimination report card, American Economic Review, 114(8), 2472-2525, doi:10.1257/aer.20230700 .
